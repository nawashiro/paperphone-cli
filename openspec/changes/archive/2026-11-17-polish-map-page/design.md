# Design

## Context

地図ページは `src/paperphone/maps.py` が 3×3〜5×5 の OSM ラスタタイルを 1024px に結合し、Pillow で白黒化して黒い線を引く。住所欄の A/B は `booklet.py` が HTML で置くが、地図画像の上には印がない。地図は 493pt 角で印刷されるため、1024px は約 149.5dpi（ほぼ 1:1）になる。設計アーカイブの「300dpi 前提」は現状と一致していない。

制約は、単一 venv、鍵なし、無人 cron、失敗時は地図だけ縮退、依存追加なし、テストはフィクスチャとモック。ベクター化は MapLibre Native が Node 20+ と Ubuntu 24.04 向け prebuilt に依存し、鍵なしの配信は OpenFreeMap（SLA なし）になるため、この変更では採用しない。ライセンス（BSD/MIT/ODbL）は障壁ではない。詳細は proposal.md を参照。

## Goals / Non-Goals

**Goals:**

- 経路と A/B を地図の主役にし、印刷したときに線の向きと位置が一目で分かるようにする。
- 既存のラスタ取得・白黒化・失敗時の縮退を保つ。
- 設定キー、依存、外部サービス、帰属表示を増やさない。

**Non-Goals:**

- MapLibre / ベクタータイル、鍵付きタイル提供元への切り替え。
- 300dpi 化（2048px 化）。ラベルの物理サイズは変わらず、タイル数だけ増える。
- タイルキャッシュ（別 change で扱う）。
- 地名ラベルの地図上への追加。住所欄と重複し、ラスタのラベルを隠す。

## Decisions

### 1. ラスタ＋Pillow のまま、描画後に印刷向けの処理を足す

地図画像を取得したあと、Pillow で「背景を薄める → 経路の縁取り → 経路の芯 → A/B」の順に描く。取得・ズーム・クロップ・白黒化の経路は変えない。ベクター案は、レンダラの追加運用手続きが地図1枠の価値を上回るため却下した（proposal.md の比較を参照）。

### 2. 背景は白8%で薄める

`convert("L")` のあと、白画像と 8% でブレンドする。0%（現状）は背景が細かく経路が埋もれ、22% は街路名が薄くなりすぎた。8% は経路が浮き、地名が読める上限に近い控えめな値。15% までは許容できるが、既定は 8% にする。設定キーにはしない。ユーザーごとの好みではなく、この冊子の印刷設計だから。

### 3. 経路は白い縁取り＋黒い芯

1024px 基準で、白 14px の上に黒 6px を重ねる。現状の黒 4px だけでは、ラスタの道路・街区の上で線の位置が読みにくい。白い縁取りはラベルを隠すが、経路の可読性を優先する。幅は `pixels / 1024` で比例させる。線の端は A/B の丸が覆うため、丸いキャップは不要。

### 4. A/B は経路の端点、経路が無ければ設定地点

経路がある場合は、描画した polyline の最初と最後の点に置く（経路サービスのスナップ先と一致する）。経路が無い場合は設定の緯度経度を投影する。丸は 1024px 基準で直径 40px、黒地に白の Varela の文字。住所欄の 14pt の丸より少し大きいが、地図上での視認性を優先する。文字は同梱の `varela_regular.otf` を使い、読めない場合は Pillow の既定フォントに落とす（地図自体は失わない）。

端に寄った地点では丸が切れないよう、中心を半径ぶん内側にクランプする。ビューポートは 20% の余白を取るので通常は発動しない。

### 5. 失敗時の意味は変えない

- 経路が取れない: 地図と A/B は描く。住所欄もそのまま。
- タイルが取れない: 画像なし。地図上の A/B も描かない。住所欄の A/B は残る。
- 画像が None のときは Pillow 処理を一切しない。

`has_route` の意味（経路線を描いたか）も変えない。

### 6. 150dpi のままにする

1024px / 493pt = 149.5dpi。2048px にするには z15 で 64 枚必要になり、取得時間とタイル数を増やす割に、ラベルの物理サイズはほぼ変わらない（地図の縮尺は同じで、ピクセル密度だけが上がる）。印刷の眠さの主因は解像度ではなく OSM Carto のラベル密度なので、この変更では解像度を触らない。アーカイブ済み design の 300dpi 記載は歴史として残し、現状はこの design を正とする。

### 7. テストは画素で確かめる

フィクスチャのタイル（一様な 200 グレー）と経路 JSON を使い、次を固定する。

- 画像は `L` モード、1024×1024 のまま。
- 経路の芯は黒（0）、縁取りは白（255）。
- 経路の端点に黒い丸があり、その中心が投影座標と一致する。
- 経路が無くても A/B が描かれる。
- タイル失敗時は画像なし。
- 背景のブレンドで、同じ画素が薄める前より明るくなる。

フォントの字形には依存せず、丸の塗りと位置だけを見る。PDF のページ数・回転・帰属の既存テストは変えない。

## Risks / Trade-offs

- **白い縁取りが街路名を隠す** → 幅を控えめにし、経路の可読性を優先する。実機印刷で気になる場合は縁取り幅だけ調整する。
- **背景を薄めすぎて地名が読めない** → 8% を上限の目安にし、22% は採用しない。実機印刷で確認する。
- **A/B が地点の街路名を隠す** → 直径 40px に抑え、住所欄にも同じ情報を残す。
- **端の地点で丸が切れる** → 中心を半径ぶん内側にクランプする。
- **同梱フォントが見つからない** → 既定フォントに落として地図を失わない。パッケージデータの欠落は別途 doctor / ビルドで検出する。
- **テストがフォント描画に敏感** → 文字ではなく丸の塗りと位置を検証する。
- **PDF が大きくなる** → 画像は 1024px の L のままで、PNG の圧縮率もほぼ変わらない。

## Migration Plan

設定・データ・保存形式の移行はない。ロールバックは `maps.py` とテストの変更を戻すだけ。印刷結果の確認は、サンプル PDF を 150dpi で画像化し、A/B と経路のコントラストを見る。物理印刷と折り畳みは従来通り手動確認。
