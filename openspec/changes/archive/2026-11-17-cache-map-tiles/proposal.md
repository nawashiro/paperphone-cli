# Proposal

## Why

OSMF のタイル利用ポリシーは、タイルを HTTP のキャッシュ指示に従ってローカルに保存することを must にしている。現状の `maps.py` は毎回 3×3〜5×5 枚を取り直し、`Cache-Control` も `ETag` も使っていない。同じ地点の地図を毎朝刷る cron では同じタイルを何度もダウンロードしており、ポリシーに沿わないうえ、コミュニティのサーバに無駄な負荷をかけている。見た目の変更とは独立に、取得層だけを直す。

## What Changes

- タイルを `XDG_CACHE_HOME/paperphone/tiles` に保存する。ファイル名は URL の SHA-256 で、座標をそのまま残さない。
- `Cache-Control: max-age` を尊重し、ヘッダが無い場合は7日を既定の鮮度とする。`no-store` は保存しない。
- 新鮮なキャッシュがあればタイル取得を省略する。
- 期限切れは `ETag` を使った条件付きリクエストにし、304 なら保存済みのバイト列と新しい鮮度を使い、200 なら差し替える。
- キャッシュの読み書きに失敗しても、地図の生成は止めずにネットワーク取得へ落とす。
- 期限切れのキャッシュをネットワーク失敗時に使う「オフライン地図」は作らない。従来通り、タイルが取れなければ地図画像を省く。
- 設定キー、依存、タイル提供元、README は変えない。
- **非目標**: 先読み・オフライン利用、キャッシュの定期削除、経路や天気のキャッシュ、7日固定 TTL への単純化、鍵付き提供元への切り替え。

## Capabilities

### New Capabilities

なし。

### Modified Capabilities

- `maps`: タイル取得にローカルキャッシュと条件付き再検証を加える。失敗時の縮退は変えない。

## Impact

- `src/paperphone/tilecache.py`（新規）: キャッシュの読み書きと鮮度判定。
- `src/paperphone/maps.py`: `fetch_mosaic` がキャッシュを経由する。
- `tests/test_tilecache.py`（新規）、`tests/test_maps.py`: キャッシュのヒット・期限切れ・破損・書き込み失敗。
- `openspec/specs/maps/spec.md`: アーカイブ時に delta を反映。
- 依存・設定・PDF・CLI の出力は変わらない。ディスク使用量はタイル数十枚分に留まる。
