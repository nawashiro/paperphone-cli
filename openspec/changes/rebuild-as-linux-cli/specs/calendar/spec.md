# Spec Delta

## MODIFIED Requirements

### Requirement: 取り込む予定の範囲

指定タイムゾーンの今日の予定だけを取り込み、開始時刻の早い順に並べなければならない (SHALL)。日の境界は `--tz`（未指定なら設定かシステム）の 00:00 から翌日 00:00 までとする。複数のカレンダーの予定は1つの一覧にまとめる。

#### Scenario: 明日の予定

- **WHEN** 明日の予定だけがあるカレンダーを選ぶ
- **THEN** その予定は冊子に含まれない

#### Scenario: 時刻順に並べる

- **WHEN** 15時と9時の予定があるカレンダーを選ぶ
- **THEN** 9時の予定が先に印刷される

#### Scenario: タイムゾーンで日付が変わる

- **WHEN** UTC では前日だが `--tz Asia/Tokyo` では今日になる予定がある
- **THEN** その予定は東京の今日の予定として冊子に含まれる

### Requirement: 予定の印刷内容

予定の枠には「CALENDAR」の見出しと区切り線を引き、予定ごとに予定名と「開始 - 終了」の時刻を印刷しなければならない (SHALL)。予定名は枠の幅に収まらない部分を切り詰める。時刻は24時間表記で、指定タイムゾーンで印刷する。終日予定は時刻を付けずに予定名だけを印刷する。

#### Scenario: 予定を印刷する

- **WHEN** 今日の予定が2件あるカレンダーを選んで生成する
- **THEN** 予定の枠に2件の予定名と「09:00 - 10:00」形式の時刻が印刷される

#### Scenario: 予定名が長い

- **WHEN** 枠の幅に収まらない長い予定名がある
- **THEN** 予定名は枠の幅で切り詰めて印刷される

#### Scenario: 終日予定を印刷する

- **WHEN** 今日が終日の誕生日予定を含めて生成する
- **THEN** その予定は時刻なしで予定名だけが印刷される

## ADDED Requirements

### Requirement: カレンダーの指定

設定の `[sources].calendars` に列挙した source UID のカレンダーだけを読み、その予定を冊子に取り込まなければならない (SHALL)。UID が見つからない、または読み取りに失敗したカレンダーは警告を出して飛ばし、他のカレンダーだけで冊子を作る。

#### Scenario: カレンダーを指定する

- **WHEN** `[sources].calendars` に1つの UID を書いて生成する
- **THEN** そのカレンダーの今日の予定が冊子の予定枠に取り込まれる

#### Scenario: 知らない UID を書く

- **WHEN** 存在しない UID を `[sources].calendars` に書いて生成する
- **THEN** 警告が出てそのカレンダーは飛ばされ、他の内容で PDF が書き出される

#### Scenario: カレンダーの読み取りに失敗する

- **WHEN** 認証が切れたカレンダーを選んで生成する
- **THEN** そのカレンダーは警告付きで飛ばされ、残りのカレンダーで冊子が作られる

#### Scenario: カレンダーを外す

- **WHEN** カレンダーの UID を設定から消して生成する
- **THEN** そのカレンダーの予定は冊子に含まれない

## REMOVED Requirements

### Requirement: カレンダーの選択

**Reason**: CLI にはカレンダーの一覧画面とチェック操作が無く、選択は設定で行う。

**Migration**: `paperphone sources` で UID を調べ、`[sources].calendars` に書く。
